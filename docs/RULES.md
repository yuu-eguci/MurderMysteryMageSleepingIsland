# ルールモデル

このソルバーが「魔法使いの眠る島」をどうモデル化しているかのメモです。

「公式ルールブックとは照合していない」。 ここに書いてあるのは、元の `foo.py` (現 `mage_island_solver/solver.py`) が前提にしていたルールと、今回モデル上で決めたことだけです。実際のゲームと食い違う可能性があります。

## 1. 実装している仮定 (元の foo.py から引き継ぎ)

公式ルールとして確認できたものではありません。元の実装が前提にしていたものを、そのまま仮定として残しています。

| 項目 | 仮定 |
| --- | --- |
| 対象 | 1ターン目の終了時点だけ |
| プレイヤー | 4人。正体 (役割) は PURPLE / RAINBOW / WHITE / BLACK を1人1つずつ |
| コード入力 | 1ゲームにつき、座席順に1人1コードずつ、計4コードを順番に実行 |
| ドローン初期状態 | HP 3、場所 INITIAL、アイテムなし |
| フィールドの初期在庫 | RED 4、BLUE 3、GREEN 2、PURPLE 3 |
| 移動コード (red / blue / green / purple) | その色の場所へ移動し、その場所のアイテムを1つ取る |
| white | 直前が黒系コードなら、今いる場所のアイテムを最大3つ取る (INITIAL では取れない)。それ以外は HP -1 |
| black | 直後が white なら無効。それ以外は HP -1 |
| black_red / black_blue / black_green / black_purple | 直後が white なら無効。ドローンがその色の場所にいれば HP -3 |
| HP 切れ | コード実行後に HP が 0 以下になったら、残りのコードは実行しない |
| HP の観測値 | 負の値もそのまま観測できるものとして、完全一致で比較する (例: `-1`) |
| アイテムの比較 | 順番は無視して、色ごとの個数で比較する |

役割ごとに使えるコード:

| 役割 | 使えるコード |
| --- | --- |
| PURPLE | red, blue, green, purple |
| RAINBOW | 全10種 |
| WHITE | red, blue, green, white |
| BLACK | black, black_red, black_blue, black_green, black_purple |

これで全部で 24 通り (役割の並び) × 800 通り (コードの組み合わせ) = 19,200 ケースになります。

## 2. モデル上の選択 (公式ルールではない)

### 在庫切れ

在庫が 0 の場所でアイテムを取ろうとしたときの公式の挙動は不明です。このソルバーでは次のように仮に決めています。

- 移動コード: 移動はする。アイテムは取れない。
- white (黒の直後): 残っている数だけ取る。0 なら何も取らない。

この仮定に頼ったケースが答えに含まれるときは、CLI が警告を出します (`relies_on_empty_stock_model`)。

警告の対象は、在庫 0 の場所でアイテムを取ろうとしたケースだけです。
white が残り1〜2個だけ取るケースは、元の実装の「最大3つ」の仮定どおりなので対象外です。

### 在庫より多く取らない

white が取る個数は、その場所の残り在庫を上限にします。
blue → black → white の場合、BLUE の取得数は初期在庫の3個を超えません。

## 3. 複数ゲームの絞り込み

ゲームごとに、観測結果と一致する「役割の割り当て (誰が何色か)」の集合を求めます。そのうえで、「割り当て全体」の積集合を取ります。

プレイヤーごとの候補だけでは、同時に成立しない組み合わせを除けません。
そのため、プレイヤー全員の役割をひとつの割り当てとして扱います。

## 4. 未確認・未対応

- 公式ルールブックとの照合 (上の表すべて)
- 在庫切れのときの公式の挙動
- 負の HP がゲーム内で実際にそう見えるのか (0 と表示される場合、HP は一致しなくなります)
- 2ターン目以降
- 上の仮定にない特殊効果やイベント

## 5. 一致するケースがないとき

あるゲームに一致するケースがないとき、または全ゲーム共通の割り当てがないときは「矛盾」として報告します (終了コード 1)。原因としては次が考えられ、ソルバーには区別できません。

- 入力ミス
- このモデルが実際のルールと違う
